# Trama MVP — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir o PWA Trama: um caderno compartilhado da criança em que cada cuidador é uma linha e cada registro é um ponto, com trama semanal e mensal, padrões automáticos, pôster compartilhável e resumo por IA.

**Architecture:** React + Vite (PWA) falando direto com o Supabase via `supabase-js`; toda regra de acesso vive no Postgres (RLS + funções `security definer`). A lógica delicada (geometria da trama e detecção de padrões) fica em funções puras testadas com Vitest. Uma única Edge Function (`gerar-resumo`) chama a API do Claude.

**Tech Stack:** React 19, Vite 6, TypeScript 5 (strict), React Router 7, TanStack Query 5, CSS Modules, `vite-plugin-pwa`, `date-fns` 4 + `@date-fns/tz`, Supabase (Auth, Postgres 15, Edge Functions/Deno), pgTAP, Vitest + Testing Library + `vitest-axe`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-29-trama-design.md`

## Global Constraints

- Idioma de toda a interface: português do Brasil. Frases em sentence case, sem caixa alta em rótulos.
- Fontes: títulos `Young Serif`; interface `Atkinson Hyperlegible` 400 e 700. Corpo mínimo 15px; rótulos do tear mínimo 11px.
- Cores (tear / fundo claro): Pau-brasil `#E8678C`/`#B3264E`; Anil `#6E8BFF`/`#3552C4`; Cúrcuma `#F2B33D`/`#8A5E07`; Erva `#4CC392`/`#226B4C`; Urucum `#F08A4B`/`#9A4413`; Ipê `#B98CF2`/`#7A4FC0`; Linha antiga `#8D96B8`/`#5A6080`. Jenipapo `#1C2238` (texto e tear). Névoa `#E9ECF0` (fundo das telas).
- A cor indica **quem**; o formato indica **o quê**. Nunca codificar tipo só por cor.
- Limites: apelido 1–30; rótulo 1–40; nome de exibição 1–40; texto do ponto até 280 caracteres (contagem por code point, igual ao `char_length` do Postgres); 6 linhas ativas por caderno; `ocorreu_em` entre agora − 7 dias e agora + 5 minutos; convite de uso único válido por 7 dias; 10 resumos por caderno por mês.
- Trama: dia das 6h às 22h no fuso do caderno (padrão `America/Sao_Paulo`); semana de segunda a domingo; trechos fortes = primeiro a último ponto da pessoa no dia, com 30 minutos de margem de cada lado.
- Padrões: regras fixas no cliente, mínimo de 3 ocorrências, prioridade noite ruim → crise, depois horário de crise, depois "funcionou" repetido. Texto do cartão: "Leitura automática dos registros. Não substitui avaliação profissional."
- Pôster: PNG 1080×1350, nunca contém texto de registros nem tipos por extenso.
- Animação: só o tecer inicial (~1,1s), o escurecer do padrão (0,45s) e o bordar ao dar ponto; tudo desligado com `prefers-reduced-motion: reduce`.
- Contraste mínimo 4,5:1 para todo texto; alvos de toque mínimo 44×44px.
- Sem analytics de terceiros. Segredos (chave da API do Claude, service role) só no servidor.
- Licença AGPL-3.0.

## Review Focus

1. **Ponto perto da meia-noite e virada de fuso:** um ponto às 23h30 em São Paulo (02h30 UTC do dia seguinte) deve cair no dia local correto e na borda direita. Teste em Task 3 e Task 4.
2. **Envio duplicado de rascunho offline:** tocar "Tentar agora" duas vezes ou a internet voltar durante um envio não pode criar dois pontos. Ids gerados no cliente + insert idempotente. Teste em Task 9.
3. **Pontos sobrepostos:** três pontos da mesma pessoa no mesmo minuto precisam ficar todos visíveis e tocáveis. Teste em Task 4.
4. **Convite em situação inesperada:** a própria dona abrindo seu convite, alguém que já é membro, convite já usado e caderno com 6 linhas ativas. Cada caso termina numa mensagem clara, nunca num erro genérico. Teste em Task 7.
5. **Responsável tentando apagar a conta:** ela não pode deixar cadernos sem dona. Recebe a mensagem e nada é apagado. Teste em Task 7 e Task 16.

## Decisões de implementação que refinam o spec

- **Tratamento da criança.** O spec escreve "o {apelido}", o que erra para meninas. O caderno ganha o campo `tratamento` (`'o'`, `'a'` ou `''`), escolhido na criação ("Como falamos dele ou dela?": "o Theo", "a Maria", "só Theo"). Todas as frases usam os helpers `nomeComArtigo` e `doApelido` (Task 2).
- **Aceitar convite e apagar conta viram funções SQL** (`aceitar_convite`, `apagar_minha_conta`) em vez de Edge Functions. São mais simples e testáveis com pgTAP. A única Edge Function é `gerar-resumo`.
- **Tabelas auxiliares:** `membros.entrou_em` (ordem das linhas) e `resumos_gerados` (contar o limite mensal).

```ts
interface Dimensoes { largura: number; xInicio: number; xFim: number; topo: number; alturaFaixa: number; margemLinha: number; espacoLinhaMax: number; afastamentoMin: number }
const DIM_SEMANA: Dimensoes; // { largura: 350, xInicio: 52, xFim: 340, topo: 16, alturaFaixa: 56, margemLinha: 11, espacoLinhaMax: 11, afastamentoMin: 10 }
const DIM_MES: Dimensoes;    // { largura: 904, xInicio: 44, xFim: 904, topo: 0, alturaFaixa: 26, margemLinha: 5, espacoLinhaMax: 6, afastamentoMin: 8 }
interface LinhaInfo { membroId: string; rotulo: string; corTear: string; corClara: string; ativa: boolean }
interface Trecho { membroId: string; x1: number; x2: number; y: number; cor: string }
interface PontoPosicionado { ponto: Ponto; x: number; y: number; cor: string; fora: 'antes' | 'depois' | null }
interface Faixa { dia: string; rotulo: string; y: number; trechos: Trecho[]; pontos: PontoPosicionado[] }
interface LayoutTrama { linhas: LinhaInfo[]; faixas: Faixa[]; altura: number; x: (hora: number) => number }
function layoutTrama(input: { periodo: Periodo; membros: Membro[]; pontos: Ponto[]; dim: Dimensoes }): LayoutTrama;
```

Regras que o implementador precisa seguir:
- Linhas: membros ativos por `entrouEm`, depois inativos que têm pontos no período, também por `entrouEm`.
- `y` da linha `i` na faixa `f`: `f.y + margemLinha + i * espaco`, com `espaco = n <= 1 ? 0 : min(espacoLinhaMax, (alturaFaixa - 2*margemLinha) / (n - 1))`.
- `x(h) = xInicio + (clamp(h, 6, 22) - 6) * (xFim - xInicio) / 16`. Ponto antes das 6h → `fora: 'antes'`; depois das 22h → `'depois'`.
- Trecho por pessoa e dia: de `min(hora) - 0.5` a `max(hora) + 0.5`, limitado a 6–22.
- Sobreposição: na mesma linha e dia, ordenar por `ocorreuEm` e `id`; se um ponto ficar a menos de `afastamentoMin` do anterior, empurrar para `anterior + afastamentoMin`; se passar de `xFim`, refazer a fila da direita para a esquerda a partir de `xFim`.

- Produces:
```ts
// _shared/pseudonimizar.ts (TS puro, sem APIs do Deno, importável pelo Vitest)
function pseudonimizar(input: { apelido: string; membros: Membro[]; pontos: Ponto[]; fuso: string }):
  { linhas: string[]; aliases: Record<string, string> };   // alias ("escola 1") → membroId
// Edge Function: POST /gerar-resumo  body { cadernoId, de, ate }  → 200 { texto, aliases } | 403 | 409 'sem_consentimento' | 429 'limite_mensal'
```

Regras de `pseudonimizar`: alias por papel na ordem de `entrouEm` ("responsável", "escola 1", "escola 2", "terapia 1", "cuidador 1"); cada linha `"{dia} {hh}h{mm} | {alias} | {tipo}{ (noite ruim)} | {texto}"`; o apelido vira "a criança"; cada rótulo completo e também seu primeiro nome (o trecho antes da vírgula, ex. "Júlia" em "Júlia, professora") viram o alias. A busca não diferencia maiúsculas e respeita limites de palavra.

Edge Function: verifica JWT, `sou_dona`, consentimento aceito e não revogado (`409 sem_consentimento`), `count(resumos_gerados)` no mês corrente < 10 (`429 limite_mensal`), busca pontos do período, pseudonimiza, chama a API do Claude (modelo da variável `ANTHROPIC_MODEL`, padrão `claude-sonnet-5-5`, `max_tokens` 1500), insere em `resumos_gerados` e devolve o texto. Instrução ao modelo: português do Brasil; seções "Visão geral", "Crises", "Conquistas", "O que funcionou", "O que cada pessoa observou"; descrever, nunca diagnosticar nem sugerir causas; usar só os aliases.

Página: escolher "Última semana", "Últimas 2 semanas" ou "Último mês"; na primeira vez, `ConsentimentoDialog` com o texto da seção 5.8 do spec e os botões "Aceitar e gerar" e "Agora não"; o cliente troca aliases pelos rótulos antes de mostrar; acrescenta a seção "Padrões encontrados" com `detectarPadroes` do período; rodapé "Este resumo descreve registros. Não é diagnóstico."; botão "Imprimir ou salvar PDF" (`window.print()`, CSS de impressão sem navegação). Erros: frase da seção 8 do spec; `limite_mensal` → "Este caderno já gerou 10 resumos neste mês. Tente de novo no mês que vem." Revogar consentimento em `/conta`.
